- Done: copy, cut and paste for entities on the canvas, by key, Edit menu and context menu. The clipboard holds source text: the selected entities and the wires between them as a fragment of the language (`docs/dsl.md`, Fragments), so a copy can be pasted into another project or into the source pane. Names get the next free number (`gate` becomes `gate2`), `tile` is dropped, a paste is one undo step and becomes the selection. Position: at the pointer when it is over the canvas, otherwise where the group was copied from, moved by (40, 40) until no copy sits exactly on an existing entity.
- Done, decided by the user on 2026-11-12 ("Add it"): Paste in the canvas context menu, on a card and on empty canvas. The copy goes to the grid point that was right-clicked. A page cannot start a paste itself, so there is one IPC channel for it, `face:edit:paste` (no arguments, trusted-sender check, the handler calls `webContents.paste()`, no clipboard content crosses IPC). Accepted cost: a compromised renderer could trigger a paste into itself and so read the clipboard text. Possible hardening, not done: refuse the call while the window is not focused. A failed call is silent (it can only fail for an untrusted sender). To verify natively: the item with a real right click.
- Done: rotation. `facing` is the direction the output points to and now decides the pin edges on the canvas; absent means east, so existing projects look as before. The pins turn rigidly (east: red above green; south: outputs at the bottom, red right of green; west: red below green; north: outputs on top, red left of green); the card and its text do not turn. R and Shift+R rotate the selection in place (one undo step), also the card context menu and a Facing control in the inspector; rotating always writes an explicit `facing` clause. Every entity rotates, lamps included, although a lamp does not in the game; the user deferred that to Milestone 3 with the work on real entities and placement (2026-11-12). Wires re-route for every edge combination; routes between two east-facing entities are unchanged.
- Done: description text. A multi-line Description box in the inspector for every entity, written as one source line (`description = "..."` with `\n`, `\t`, `\r` escapes), a marker on the card and the text in its tooltip. Save also writes text that is still being typed. Decided by the user (2026-11-12): every entity keeps the box and its text is preserved in the project, also where the game has no description field (it has one on combinators only, `docs/factorio-audit.md` 3.2); such text is then simply not present in the game. No length limit is enforced because the audit states none.
- Done: the [R] and [G] boxes are grayed (dashed outline, no wire color, still operable) when no wire of that color is connected to the entity's input, as the game does.
- Done: both [R] and [G] can be unchecked, as the game allows. The language writes it as `[none]` after a signal and `networks = none` for the lamp (`none` is not a reserved word); a signal read from no network counts as absent (rule N-NONE in `packages/simulation/CONFORMANCE.md`, assumed).

The gray square is gone; an input without a wire has a dimmed marker.

## Project file follow-ups

- Custom icons: `assets/` entries must be read and preserved on save once they exist; today saving writes only `face.json` and the circuits, so any other entry of a hand-built archive is lost.
- No CRC check on read (fflate does not verify it): a deflated entry that declares less than it holds is cut at the declared size instead of being refused. Needs own central-directory parsing or a different reader.
- Archives made with Finder's Compress are refused (`__MACOSX/` entries, or everything below a top folder); so is any entry name containing `..`. Decide whether to ignore such entries instead.
- No file association and no `open-file` handling for `.faceproj` (double-click in Finder) until packaging.
- Stale entries stay in Open Recent after a failed load; with unsaved changes the Save/Discard prompt comes before the load fails. An error banner is not cleared by a later successful save.
- Zip and unzip run synchronously in the main process; the write-side size limits have no test.
- If projects should live in version control: a folder export/import.

## Language follow-ups (from the language package report)

- Model states the language cannot express are reported as `unrepresentable` by commands and silently normalized by the printer. Decide per case before blueprint import: a condition without a first signal (decider, lamp), an arithmetic combinator without output, lamp `colorMode` without `useColors`, a decider output constant other than 1 while copying input, network selection on a constant output or on a selector index signal.
- Hexadecimal literals above `0x7FFFFFFF` are rejected; consider two's-complement masks (`0xFFFFFFFF`).
- `docs/dsl.md` must absorb the implemented choices: header clauses in any order, separators between members, single-line strings, `source = signal` wording, the extra diagnostic codes (`invalid-statement`, `invalid-signal`, `duplicate-signal`, `contradictory-statement` for selector properties), wildcard legality per slot, canonical print rules.
- Shorthand for virtual signals (open point for the user's language review).
- Components: `import`, `component`, `port` are reserved only.
