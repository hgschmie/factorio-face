## Blueprint books (requested 2026-11-19)

The user, 2026-11-19: "For blueprints, we also need to implement blueprint books. Those are collections of blueprints. I want to be able to load a blueprint book into a project, similar to how I load a blueprint. Then I want to be able to select a blueprint from the book and work on it. In addition to the existing blueprint export options, there should also be "export to blueprint book (either add as a new blueprint in the book or overwrite an existing blueprint). A blueprint book should be as exportable as a blueprint (either a file or a string)." The plan was put to the user the same day and accepted with the coordinator's defaults for both decisions ("Build it").

- Model: a project holds at most one book, kept as the game wrote it (its blueprint string, one more entry of the project file), next to the one circuit. Items never opened, planners, books inside the book, descriptions and icons stay untouched; an unchanged book exports as the string it came in as. Choosing a blueprint from the book replaces the circuit as one undo step and switches on the mods it needs. "Export to book" writes the circuit into the stored book: as a new blueprint at the end of the book or of a book inside it, or over an existing blueprint, which keeps its slot. The book exports as a file or as a string in a dialog. A change to the book marks the project as changed.
- Decision 1 (default accepted): overwriting replaces the whole blueprint, so what the editor does not hold (rails, pipes, walls, tiles) is gone from it; the dialog says how many entities are lost and asks. Overwriting the blueprint the circuit came from keeps its description, icons and snapping. Putting the dropped entities and tiles back in on overwrite was offered as a follow-up and not chosen.
- Decision 2 (default accepted): entity names, comments and card positions are not in a book; choosing a blueprint a second time gives fresh names. A circuit file per opened blueprint was offered as the alternative and not chosen.
- Not in the plan: reordering, renaming or deleting items of a book, creating an empty book, editing planners.
- A project with a book gets a higher format number, so that an older build refuses it instead of dropping the book on save.
- Stages: 1 a recording of a book from the game (the audit has the fields from the web only, nesting unverified); 2 `@face/blueprints`: add to and replace in a book; 3 the project file; 4 the session; 5 dialogs and menu (File > Blueprint Book: Choose Blueprint, Load Book From File, Paste Book, Export As File, Show Book String, Remove Book; File > Export Blueprint > To Blueprint Book; a line in the window that names the book and the item the circuit came from; the import dialog keeps the book).

- Built on 2026-11-19, all five stages: `78517cc` (probe and fixture F-30), `f426a6c` (package: `addToBook`, `replaceInBook`, `canonicalBlueprintString`), `ddd248a` (project file: entry `book.txt`, `"book": { "file", "origin" }` in face.json, format version 2 with a book and 1 without), `274203f` (session), and the dialogs, menu and status line in the commit after it. 3340 unit tests pass, the build succeeds. `tests/e2e/blueprintBook.spec.ts` (11 tests) is written and NOT run; nothing was seen in a window. - Game facts from F-30 that differed from the plan: a book has 65535 slots (`index` 0 to 65534; beyond that the game drops the item and `import_stack` returns -1); an item without `index` goes to the first empty slot, and of two items with the same `index` the first stays. A new blueprint therefore gets the slot after the last one in use, the first empty slot when the last is taken, and the add is refused when the book is full. `active_index` is left as it is.

A stored book that cannot be read stays in the project file as it is and can only be removed or replaced. An import of a book always keeps the book; a book without a usable blueprint opens as a project without a circuit. Menu items are not disabled without a book: the command opens a dialog that says so and offers to load one. No accelerators for the book commands. The line that names the book is in the status line, not above the canvas.
